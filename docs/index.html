The point of this project

Every line is agent-authored

This repository is a working demonstration of AI-native software development. A human sets the direction in a sentence or two; an AI agent — Claude Code (Anthropic's Sonnet) — does the exploration, the architecture, the code, the migrations, the deploys and the docs. AI-native toolchain

Tools built for agents, not just for people

The interesting parts of the stack are the ones that assume an AI is in the loop.

Vercel Labs

agent-browser

A browser-automation CLI made for agents. It returns the page as an accessibility tree with stable element refs (@e1, @e2…) instead of raw HTML or brittle selectors — so the agent can open a route, snapshot it, click, type and re-snapshot with a fraction of the context a normal browser tool would burn. Used here to verify UI changes against the running dev servers.

The product

Two views of one workflow

apps/hazy · app.example.com

hazy

Drop a link and forget it. Later: full-text search over everything you've saved, an "Ask" that answers from your reading (RAG over your own library), collections, and a read-later digest that buckets by how long things take.

  • Frontend only — Next 16, React Compiler, next-intl (en/ja)
  • Talks to the API over a Clerk bearer token + CORS
apps/hazy-note · note.example.com

hazy note

Capture sources → gather them into a project (a space to develop one idea) → write notes in a Quill rich-text editor with @-cite → compare sources on a board → export to a blog post, memo or bullets.

  • Quill editor — the note body is a Delta stored in Postgres
  • Its own /api/* handlers over the shared schema
Architecture

Three Workers, one database, one contract

Same Clerk tenant → same users.id → hazy and hazy note share saved_urls and collections. A URL saved in one shows up in the other.

browser ──▶ app.example.com (hazy — Next / OpenNext Worker, no backend) │ Authorization: Bearer <clerk jwt> ▼ api.example.com (hazy-api — a Hono Worker, /v1/**) │ browser ──▶ note.example.com ─────────┤ (hazy note — Next / OpenNext Worker + its own /api/*) ▼ @repo/db ──▶ Postgres (Neon) (one Drizzle schema, dual-driver client) @repo/api-client the typed wire contract shared by the frontend and any future native client
packages/db

@repo/db

One schema, migrations, the search-vector trigger. getDb() picks postgres.js locally, Neon's HTTP driver on Workers.

packages/api-client

@repo/api-client

The DTO contract + a typed client (useHazyClient()). Single source of truth for the API shape.

turbo · bun

Monorepo

bun workspaces, Turborepo tasks, Biome. Each app deploys independently via wrangler / OpenNext.
